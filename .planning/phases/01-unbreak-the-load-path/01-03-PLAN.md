<objective>
Close the unauthenticated shell-injection route into a file that is later executed with
`bash`, and make `verify_auth` stop being a silent no-op on a non-loopback bind.

Purpose: REQ-03. Both halves are confirmed. `config.json` has no `api_key` and `app.host` is
the tailnet address `100.115.54.83`, so `verify_auth` returns immediately on every
`Depends(verify_auth)` endpoint. `POST /api/vllm/profiles/from-hf` then carries `model_name`
into `--served-model-name "{info['name']}"` unquoted, and `$(...)` executes inside double
quotes. Generating with `model_name='evil$(id > /tmp/dgx-pwn-proof)'` reproduced the
substitution verbatim in the script text. `_safe_profile_slug` sanitises the *filename* and
`_path_under` proves directory containment; neither is shell escaping. The reachable path is a
flat or custom directory, because `_profile_model_info` overwrites `model_name` whenever a
`models--*` ancestor exists.

Output: grammar validation plus `shlex.quote` defence-in-depth across the generator, and an
auth layer that fails closed or logs loudly but never silently permits.
</objective>

app.py:924-947 — `_lifespan`. It already detects the non-loopback + no-key case and, unless

app.py:2939 — `POST /api/auth/check` returns `{"ok": True, "auth_required": False}` whenever no

app.py:2283 — `_safe_profile_slug(name) -> str` collapses everything outside

  <name>Task 1: Validate and shell-quote every dynamic atom in the generator</name>
  <files>app.py, tests/test_vllm_profile_generation.py</files>
  <behavior>
    - `_build_vllm_profile_script(dir, "evil$(id > /tmp/x)")` raises HTTPException 400; the
      string `$(id` never appears in any generated script.
    - The same holds for a name containing a backtick, a double quote, a single quote, a
      newline, a semicolon, or a NUL.
    - A legitimate name such as `Qwen/Qwen3.6-35B-A3B-FP8` is accepted unchanged.
    - A model directory whose path contains a space and a single quote still produces a script
      that passes `bash -n`, with the host path quoted.
    - A `vllm.moe_backend` or `vllm.image` value containing shell metacharacters is rejected or
      quoted, never emitted raw.
    - Every generated script in the test suite passes `bash -n`.
    - The `# Name:` / `# Description:` header lines cannot be broken out of by a newline in any
      input.
  </behavior>
  <action>
    Add `shlex` to the stdlib imports at the top of app.py.

    Grammar first, quoting second — both, not either.

    1. Add a served-name grammar constant, for example a compiled pattern accepting
       `[A-Za-z0-9._/-]{1,128}` anchored end to end, and validate `model_name` in
       `_build_vllm_profile_script` immediately after `_profile_model_info` returns (validate
       `info["name"]`, so a name recovered from a `models--*` ancestor is checked too). On
       failure raise `HTTPException(400, ...)` naming the allowed character set. Reject control
       characters explicitly so a newline can never reach the comment header. This is the
       primary defence and is what makes the injection unreachable.

    2. Apply `shlex.quote` as defence-in-depth to every dynamic atom that reaches the script
       body: `container_model` in the `--model` line, both names in `--served-model-name`, the
       resolved `image`, and `_moe_backend`. Drop the surrounding hand-written double quotes
       when you do — `shlex.quote` supplies its own quoting and double-quoting its output would
       reintroduce `$(...)` evaluation. Note that `vllm-active` is a literal and needs no
       quoting.

    3. In `_container_model_mount`, quote the host side of the mount for the two branches that
       interpolate a real filesystem path (the `models--*` repo-root branch and the flat-dir
       branch). Leave the HF-cache branch exactly as it is: that line is a constant and
       deliberately relies on the shell expanding `$HOME` at launch time — quoting it would
       turn `$HOME` into a literal and break every cache-backed profile. Add a comment saying
       so, because it looks like an oversight otherwise.

    4. For the comment header, sanitise rather than quote: strip or replace newlines and
       carriage returns in `info['name']` and `launch_dir` before interpolation, so the
       `# Name:` and "Auto-generated ... from:" lines stay single lines. `_parse_script_meta`
       reads those headers, so keep them on one line each.

    5. Validate `_moe_backend` against a conservative pattern (lowercase letters, digits,
       underscore) and keep the existing "empty means omit the flag" semantics.

    Update `tests/test_vllm_profile_generation.py`: adjust the existing mount, `--model` and
    `--served-model-name` assertions to the exact text the quoted generator now emits, and add
    the behaviors above. Include the recorded exploit string `evil$(id > /tmp/dgx-pwn-proof)`
    verbatim as a regression case, asserting both the 400 and that `$(id` is absent from any
    output. Reuse the `bash -n` helper added in plan 01-02. Never execute a generated script.
  </action>

    - No key, non-loopback host, `MODEL_MANAGER_ALLOW_UNAUTH=1` → returns None AND logs a

    401 paths byte-identical. Replace the opening `if not _API_KEY_HASH: return` with a branch

    Update `POST /api/auth/check` to report the truth instead of `auth_required: False`: keep

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tailnet HTTP client → FastAPI | Every mutating endpoint; currently unauthenticated in practice |
| FastAPI → generated start script | Request-supplied `model_name` reaches a file later run with `bash` |
| generated script → docker daemon | Docker access on this box is root-equivalent, so script execution is effectively root |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-08 | Elevation of privilege | `model_name` → `--served-model-name` in `_build_vllm_profile_script` | mitigate | Anchored served-name grammar rejecting anything outside `[A-Za-z0-9._/-]` plus `shlex.quote` on every interpolated atom. Regression test uses the recorded exploit string. |
| T-01-09 | Elevation of privilege | mount host paths in `_container_model_mount` | mitigate | `shlex.quote` the host side of the repo-root and flat-dir branches; leave the constant `$HOME` cache mount unquoted with an explanatory comment. |
| T-01-10 | Spoofing | `verify_auth` no-op on a non-loopback bind | mitigate | Fail closed with 503 unless `MODEL_MANAGER_ALLOW_UNAUTH` is set; when set, log every unauthenticated mutating request with method and path. Never silent. |
| T-01-11 | Elevation of privilege | `PUT /api/config` as a credential-installation path | mitigate | Covered by the same 503: an unauthenticated remote caller cannot install the first key. Bootstrap is config.json or loopback, recorded in a comment. |
| T-01-12 | Tampering | `vllm.image` / `vllm.moe_backend` from config.json | mitigate | Validate `moe_backend` against a conservative pattern and quote the image. Operator-owned input, but quoting costs nothing and removes the class. |
| T-01-13 | Repudiation | unauthenticated mutations leave no trace | mitigate | The degraded path logs method and path at WARNING, so the acknowledged-open deployment still produces an audit trail. |
| T-01-SC | Tampering | package installs | n/a | No new packages. `shlex` is stdlib; `starlette` ships with FastAPI. |
</threat_model>
