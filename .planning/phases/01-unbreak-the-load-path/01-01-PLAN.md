<objective>
Fix the `NameError: _HF_XFER` that makes every HuggingFace download fail, and make the
download stream structurally incapable of ending without a terminal event.

Purpose: REQ-01. The download → auto-profile → launch path is dead at step one. Worse, it
fails *silently*: the NameError fires before the worker enters its `try`, the parent never
checks `proc.returncode`, and stderr is turned into `log` events the HF UI discards — so the
progress area just spins forever.

Output: A worker script that starts cleanly, a parent stream that always emits exactly one
`complete`/`error`, and offline regression tests for both.
</objective>

    - A stdout line that is not valid JSON is forwarded verbatim and does not produce an

    module-level async generator so it is directly testable — for example
    `async def _hf_download_events(sub_env: dict, repo_id: str, dl_key: tuple) -> AsyncGenerator[str, None]`.
    `hf_download` keeps all its existing validation and duplicate-download guarding and simply
    returns `StreamingResponse(_hf_download_events(sub_env, repo_id, dl_key), ...)` with the

    1. Track terminal state with a local flag. Define a small module-level predicate
       `_is_terminal_hf_event(ev: dict) -> bool` returning True when `ev.get("status")` is

       arrives, forward it as a non-terminal `{"log": ...}` instead of a second terminal.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tailnet HTTP client → FastAPI | `POST /api/hf/download` body (`repo_id`, `local_dir`, patterns) is untrusted |
| FastAPI → worker subprocess | Values cross as environment variables, never as script text |
| worker → huggingface.co | Remote repo listing and file content is untrusted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | `repo_id` / `local_dir` reaching the worker | mitigate | Already enforced upstream and must be preserved: `_HF_REPO_RE` grammar, NUL/newline rejection on `local_dir`, `_allowed_model_roots` containment, and passing input via `sub_env` rather than interpolating into `_HF_DOWNLOAD_SCRIPT`. Do not change this contract while restructuring `stream()`. |
| T-01-02 | Information disclosure | synthesized error event | mitigate | The stderr tail is echoed to the SSE client. Cap it (~2000 chars) and emit only the worker's own stderr — never `sub_env`, which carries HF tokens and the process environment. |
| T-01-03 | Denial of service | orphaned worker on client disconnect | mitigate | Keep the existing `finally` terminate-and-discard; a child blocked on a full stdout pipe holds `_active_downloads` and blocks all later downloads of that repo. |
| T-01-04 | Repudiation | silent worker death | mitigate | This plan's core fix: a non-zero exit or missing terminal event is always reported, so a failed download can no longer look like an in-progress one. |
| T-01-SC | Tampering | package installs | n/a | No new packages. `importlib`, `shlex`, `json`, `subprocess` are stdlib; `huggingface_hub` and `pytest-asyncio` are already dependencies. |
</threat_model>
