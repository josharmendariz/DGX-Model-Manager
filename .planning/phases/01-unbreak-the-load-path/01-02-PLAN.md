<objective>
Make the `vllm serve` subcommand a property of the container image instead of a property of
the model family, and regenerate the two committed DeepSeek profiles that predate the
mount-scope fix.

Purpose: REQ-02. `config.json` sets `vllm.image: eugr/spark-vllm:latest` for *every* model,
but the generator only prepends `vllm serve` when the model name contains "gpt-oss". That
image's entrypoint is `/opt/nvidia/nvidia_entrypoint.sh` with a null CMD — it execs whatever
arguments it is given — so every generated non-gpt-oss script hands it `--model ...` with
nothing to exec. Confirmed in the committed artifacts: the generated
`start_hf_qwen_qwen3.6-35b-a3b-fp8.sh` goes straight from the image line to `--model`, while
the hand-written, known-good `start_hf_qwen_qwen3-8b.sh` includes `vllm serve`.

Output: an image-derived serve prefix with a config escape hatch, two regenerated DeepSeek
profiles, and a guard test that stops stale profiles from silently accumulating again.
</objective>

       `moe_backend` idiom where empty means omit.

       `vllm-openai` returns empty; every other image returns "vllm serve". Strip any
       `@sha256:` digest suffix before matching. Defaulting unknown images to the explicit form
       is the safe direction — `vllm serve` also works when passed as the container command to
       an image whose entrypoint execs its arguments, which is what nvidia_entrypoint.sh does.

    trailing-backslash convention of the surrounding arg lines. Remove `is_gpt_oss` from the

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| config.json → generated script | `vllm.image`, `vllm.serve_command` and `vllm.moe_backend` are interpolated into a file later run with `bash` |
| generated script → docker daemon | Docker access on this box is root-equivalent |
| host filesystem → container | `-v` mounts decide what the container can read |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Elevation of privilege | `vllm.serve_command` / `vllm.image` interpolated into the script | transfer | config.json is operator-owned and already root-adjacent (it selects the container image). Plan 01-03 adds shlex quoting and grammar validation across every dynamic atom in the generator, including these; do not hand-roll a second escaping scheme here. |
| T-01-06 | Tampering | `:latest` image tag | accept | `eugr/spark-vllm:latest` can silently change entrypoint shape under the operator. Mitigated behaviorally by `_vllm_serve_command` defaulting unknown images to the explicit `vllm serve` form, which works under both shapes. Digest pinning is deliberately out of Phase 1 scope. |
| T-01-07 | Information disclosure | container mounts | mitigate | The regenerated scripts widen the mount from `snapshots/<rev>` to the `models--*` repo root. That is the minimum scope in which the relative blob symlinks resolve, it stays `:ro`, and it never reaches above the repo root. The guard test asserts no mount is narrower (dangling) — reviewers must also confirm none is wider. |
| T-01-SC | Tampering | package installs | n/a | No new packages. All changes use stdlib plus existing test dependencies. |
</threat_model>
