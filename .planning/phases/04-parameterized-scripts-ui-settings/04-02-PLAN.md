  <files>app.py, tests/test_vllm_profile_generation.py</files>

  <action>
    Extend `_vllm_script_preamble` — the single owner of generated metadata — to emit three
    additional header comments in the first 20 lines, each a single line of compact JSON so the
    parser has one unambiguous shape:
      `# Derived: {"max_model_len": N, "max_fitting_context": N, "declared_max_context": N, "max_num_seqs": N, "util": F}`
      `# Recommended: {"gpu_memory_utilization": F, "max_model_len": N}`
      `# Warnings: [...]`
    plus `# Generated: <ISO-8601 timestamp>` so staleness is visible.
    Thread the full `_derive_launch_spec` result and `info["warnings"]` into the preamble —
    today `_resolve_launch` drops the other fourteen keys before the preamble is built, so the
    call site must pass the spec through rather than re-deriving.

    The header is now a versioned data format. Include a `"v": 1` key in the `# Derived:` object.
    Escape/one-line every string in `# Warnings:` — warning strings embed `{value!r}` of
    vendor-supplied config fields, so a newline in one would break the header contract.

    Recipe-backed scripts: emit `# Derived:` with an explicit `"editable": false` and the reason,
    since the YAML owns their flags.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| script header → server parser | Header JSON is written by the generator but read from a user-writable directory |
| parsed header → DOM | Derived values and warning text (embedding vendor config fields) reach the browser |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06 | Tampering | `# Derived:` header in a hand-edited script | mitigate | header values are display-only; the launch still resolves through `_OVERRIDE_ENV` validation and the script's own numeric guard |
| T-04-07 | Information Disclosure | warning strings embedding `{value!r}` of config fields | mitigate | warnings rendered via `textContent` here, `esc()` in 04-03 |
| T-04-08 | Denial of Service | `_scan_profiles` doing per-profile config reads | mitigate | Option A forbids filesystem reads in `_parse_script_meta`; asserted by Task 2 |
| T-04-09 | Spoofing | a stale header advertising a context the model no longer supports | accept | `# Generated:` timestamp makes staleness visible; recompute-on-read is the deferred Option B |
| T-04-SC | Tampering | package installs | mitigate | none — no packages installed by this phase |
</threat_model>
