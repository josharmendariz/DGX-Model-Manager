<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP body → `_engine_start` | Untrusted override map from the browser crosses into server state |
| `Popen(env=)` → bash script | Override values become shell variables and then docker argv |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | `_engine_start` overrides param | mitigate | `_OVERRIDE_ENV` name allow-list + per-value validator; unknown key → 400 (Task 2) |
| T-04-02 | Elevation of Privilege | generated script variable expansion | mitigate | numeric guard block in the script exits before `docker run` on a non-numeric value (Task 1) |
| T-04-03 | Denial of Service | admission bypass via a large context override | mitigate | overrides resolved before `_vram_admission_check` (Task 3) |
| T-04-04 | Tampering | script file at launch | accept | `_engine_start` performs no writes; writes stay in `_create_vllm_profile_from_path`'s atomic tmp→`os.replace` |
| T-04-05 | Information Disclosure | full `os.environ.copy()` into the child | accept | pre-existing behavior, unchanged by this phase; the child is a trusted local launch script |
| T-04-SC | Tampering | package installs | mitigate | none — this phase installs no packages (04-RESEARCH.md §Environment); nothing to slopcheck |
</threat_model>
