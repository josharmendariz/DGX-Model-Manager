  <files>app.py, tests/test_profile_meta.py</files>
  <read_first>
    app.py:4501-4526 (`_create_vllm_profile_from_path` — the atomic write and the 409 precedent);

    §"Don't Hand-Roll" rows for diff, atomic write and content-change detection.

  <action>
    Add a pure `_parameterize_script_text(text) -> tuple[str, list[str]]` that rewrites each
    literal flag value into the matching `${VLLM_*:-<literal>}` placeholder from 04-01, preserving
    the original number as the default so behavior is unchanged, and returns the notes describing
    what was and was not rewritten. Refuse (raise) when any target flag is `unparseable` — a
    partial rewrite of a hand-tuned script (the 60-line gpt-oss one carries a root-cause writeup)
    is destructive and irreversible.

    Add a preview endpoint returning `{current, proposed, diff, sha256, notes}` where `diff` is
    built server-side with `difflib.unified_diff` and `sha256` is `hashlib.sha256` of the current
    file text. Do not build the diff in JS — the client must not hold or resend script text.

    Add an apply endpoint requiring that `sha256` back. Re-read the file, recompute the hash, and
    on mismatch return 409 naming the change, writing nothing — the repo has ~3 concurrent sessions
    sharing the profile directory. On match, write a `.bak` sibling first, then write via the
    existing tmp → `os.chmod(0o755)` → `os.replace` idiom. Never `path.write_text` directly.

    Both endpoints go behind `Depends(verify_auth)` like the rest of the mutating API.
  </action>

    - `pytest tests/test_profile_meta.py -k stale_hash` passes: preview, mutate the file, apply

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| hf.co API response → browser DOM | Third party names the repo; the string reaches `innerHTML` |
| script header / filename → browser DOM | Any `start_*.sh` in the profile dir supplies `# Name:` / `# Description:` |
| HTTP apply request → profile script on disk | The only write path to an executable file in this phase |
| preview call → apply call | Two HTTP calls with a mutable file between them |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-10 | Tampering (stored XSS) | `renderHFBCard` at app.py:8655/8661 | mitigate | `esc()` on `m.id`, `m.library_name`, `m.tags` and both `id=` attributes (Task 3) |
| T-04-11 | Tampering (XSS) | profile-card template at app.py:7971-7990 | mitigate | `esc()` on `${p.name}` / `${p.description}`; `esc(q(x))` or dataset+delegated listener on the `onclick` attributes (Task 3) |
| T-04-12 | Tampering (TOCTOU) | parameterize preview → apply | mitigate | sha256 confirm-token required on apply; 409 on mismatch, nothing written (Task 2) |
| T-04-13 | Elevation of Privilege | apply endpoint writing a 0o755 executable | mitigate | `Depends(verify_auth)`; rewrite is generated by a pure function from the file's own text, never from request-supplied script content |
| T-04-14 | Repudiation / data loss | destructive rewrite of a hand-tuned script | mitigate | `.bak` written first; refuse entirely on any `unparseable` target flag (Task 2) |
| T-04-15 | Information Disclosure | warning text embedding `{value!r}` config fields | mitigate | rendered via `textContent`/`esc` (Task 3) |
| T-04-16 | Spoofing | `q()` mistaken for an HTML escaper | mitigate | exactly one `esc` helper plus the source-text guard test; `grep -c "const esc"` == 1 |
| T-04-SC | Tampering | package installs | mitigate | none — `difflib`, `hashlib`, `re` are stdlib; no packages installed, nothing to slopcheck |
</threat_model>
